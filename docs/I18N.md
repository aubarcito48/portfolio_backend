# Contenido público en español e inglés

El idioma predeterminado es español. Los endpoints de contenido admiten `lang=es`
y `lang=en`; por ejemplo, `/api/v1/perfil/?lang=en` y
`/api/v1/proyectos/?lang=en&page_size=1`. Las respuestas indican
`Content-Language` y conservan sus campos JSON. La paginación conserva `lang`.
Un idioma no admitido devuelve HTTP 400. Las escrituras públicas siguen rechazadas.

`portfolio/localization.py` contiene las traducciones revisadas de la biografía,
experiencia, formación, categorías de tecnologías, proyectos, textos alternativos,
etiquetas de enlaces y errores. El español muestra también la especialidad y
el título del certificado en español, sin cambiar sus valores almacenados.
Los nombres propios de personas, instituciones y productos se conservan.

No hay traducción automática externa, suscripciones ni claves nuevas. No se
modifican PostgreSQL, migraciones, permisos, fechas, orden, slugs, relaciones,
URLs ni archivos. Los borradores nunca se incluyen por elegir otro idioma.
Las rutas `/assets/...` siguen perteneciendo al frontend.

## Mantener las traducciones

Al agregar o editar texto en Django Admin, agregar su versión inglesa a `ENGLISH`
en `portfolio/localization.py`. Las claves son el texto original exacto; los
párrafos separados por saltos de línea pueden traducirse por línea. Si falta
una traducción se muestra el texto original, sin reemplazarlo por un mensaje
vacío ni una traducción antigua. Los enlaces o documentos externos mantienen
su contenido y su idioma originales.

Los textos de interfaz, carrusel, navegación, carga, vacío, error y accesibilidad
se administran en `cv-proyecto/src/app/shared/data/translations.ts` con Transloco
8.4.0. El selector ES/EN guarda `portfolio-language` en el navegador, actualiza
`html[lang]` y los metadatos, localiza meses y solicita de nuevo los seis recursos.
Las solicitudes anteriores se cancelan para que una respuesta tardía no reemplace
el idioma actual. Si el navegador bloquea el almacenamiento, el selector sigue
funcionando durante la visita. No se cambia la preferencia del tema.

## Publicación y comprobación

1. Subir y desplegar primero el backend en Render.
2. Comprobar `/api/v1/perfil/?lang=en`: HTTP 200, `Content-Language: en` y
   biografía que empieza por `I am a software developer`. El endpoint sin `lang`
   sigue respondiendo en español.
3. Subir el frontend y esperar el despliegue de Vercel.
4. Cambiar ES → EN, comprobar biografía, experiencia, proyectos y fechas;
   recargar para verificar la preferencia, y volver a ES. Revisar también móvil,
   tema, enlaces y certificado en pestaña nueva.

No se requieren variables de entorno nuevas ni migraciones. Se conserva la URL
de Render de producción y la URL local de desarrollo. Publicar solo el frontend
con el backend anterior traduciría la interfaz pero conservaría el contenido
de la API en español.

## Pruebas

Con PostgreSQL local y una base de tests independiente, como indica el README:

```powershell
.\.venv\Scripts\python.exe manage.py test portfolio.test_localization --noinput
.\.venv\Scripts\python.exe scripts/run_regression.py
```

La regresión crea una base local transitoria y verifica ambos idiomas contra
Django real en Chromium, Firefox y WebKit, a 360, 768 y 1440 px. Incluye
persistencia del idioma, contenido, paginación, fechas y recuperación de errores.
No ejecutar estos tests contra Supabase ni Render. Los reportes de ejecución
se guardan en `reports/`; la validación de este cambio se resume en `reports/I18N.md`.
